# 9. 인증 & 마이페이지 (`/[locale]/me`)

## 9.1 인증 설계 원칙

| 원칙 | 내용 |
|---|---|
| **게스트 우선** | 로그인 없이 **모든 조회 기능**을 100% 쓸 수 있다. 로그인은 "저장·알림·기록"에서만 요구한다. 관광객(G11)이 회원가입 벽을 만나면 안 된다 |
| **익명 → 정식 승격** | 첫 즐겨찾기 시 Firebase **익명 인증**으로 조용히 계정 생성 → 이후 정식 로그인 시 `linkWithCredential` 로 데이터 승계 |
| **로컬 우선 저장** | 즐겨찾기·최근 본 지역·설정은 즉시 localStorage에 쓰고, 로그인 시 Firestore와 병합(충돌 시 `updatedAt` 최신 우선) |
| **최소 수집** | 이메일/닉네임 외 개인정보 수집 금지. 위치는 저장하지 않고 요청 시점에만 사용(즐겨찾기 지점 제외) |

## 9.2 로그인 수단 & 세션

```
Firebase Authentication
  - Google
  - Apple  (iOS Safari/PWA 대응)
  - Kakao  (Firebase Custom Token: /api/auth/kakao 에서 Kakao OIDC 검증 후 createCustomToken)
  - Email link (passwordless)   ← 비밀번호를 다루지 않는다
  - Anonymous (게스트 승격용)
```

**세션 처리 (Vercel + Firebase)**
```
클라이언트 로그인 → ID Token 획득
  → POST /api/auth/session  (Firebase Admin SDK)
  → createSessionCookie(idToken, { expiresIn: 14d })
  → httpOnly / secure / sameSite=lax 쿠키 `__barum_session` 설정
middleware.ts
  → 로케일 협상 + /me, /admin 경로에서 쿠키 존재 확인(경량 검사)
Server Component / Route Handler
  → verifySessionCookie(cookie, checkRevoked=true) 로 uid·role 확보
로그아웃 → revokeRefreshTokens + 쿠키 삭제
```
- Firebase Admin 자격증명은 Vercel 환경변수 `FIREBASE_SERVICE_ACCOUNT_JSON`(base64) 로 주입. **절대 클라이언트 번들에 포함 금지 (R4)**
- Node.js 런타임 라우트에서만 Admin SDK 사용(Edge 런타임 비호환). middleware는 쿠키 존재 여부만 확인하고 실제 검증은 라우트에서 수행.
- **App Check**(reCAPTCHA Enterprise) 를 Firestore·Functions·주요 API에 강제해 어뷰징 차단.

## 9.3 마이페이지 정보 구조 — 왜 이렇게 나눴는가

마이페이지는 흔한 "설정 모음"이 아니라 **개인화 엔진의 입력 화면**이다. 여기서 모은 것이 §7 해석 엔진과 §14 알림의 정확도를 좌우한다.

```
/me  (허브)
├─ 프로필 헤더              — 정체성
├─ ① 내 장소                — "어디를" 보는가      → 홈 카드 순서·알림 대상
├─ ② 내 활동 프로필         — "왜" 보는가          → 해석 엔진 가중치 (핵심)
├─ ③ 내 알림                — "언제" 알려줄까      → FCM 규칙
├─ ④ 내 기록(로그북)        — "무엇이 좋았나"      → 개인화 학습 + 재방문 동기
├─ ⑤ 내 제보                — 커뮤니티 기여
├─ ⑥ 저장한 여행/코스       — 여행 탭 연계
├─ ⑦ 앱 설정                — 언어/단위/테마/지도
├─ ⑧ 계정·보안·데이터
└─ ⑨ 지원·정보
```

## 9.4 각 항목 상세 명세

### ① 내 장소 (`/me/places`)
- 즐겨찾기한 지점 카드 리스트. 각 카드에 **현재 기온·파고·물때 요약**이 실시간으로 표시된다(정적 목록이 아니다).
- 드래그 정렬 → **이 순서가 홈 화면 빠른 전환 칩 순서와 동일**하게 반영된다.
- 지점별 토글: `홈에 고정` / `알림 대상` / `오프라인 캐시`
- 유형 구분: 해변 / 항구 / 갯바위 / 오름 / 자유 좌표(롱프레스로 저장한 위치)
- 최대 30개, 초과 시 정리 유도
- 게스트도 사용 가능(로컬 저장) — 로그인 시 자동 병합

### ② 내 활동 프로필 (`/me` 내 인라인 편집) — **가장 중요한 항목**
사용자가 자기 조건을 한 번 입력하면, 이후 모든 판정 문장이 그 기준으로 바뀐다.

```
관심 활동 (복수 선택, 드래그로 우선순위)
  □ 서핑  □ 낚시  □ 해루질/갯벌  □ 다이빙/스노클  □ 드라이브  □ 사진/노을  □ 캠핑  □ 해수욕

숙련도 (활동별)
  ○ 입문  ○ 중급  ○ 상급        → 위험 컷오프 임계값이 달라진다
                                    (입문은 파고 1.5m에서 이미 caution)

선호 조건 (활동별, 슬라이더 — 기본값은 §7.2 표에서 자동 채움)
  파고   [0.6 ────●────── 1.8] m
  풍속   [0   ──●──────── 6  ] m/s
  선호 풍향  ○ 상관없음  ● 서~북서   (오프쇼어 판정)
  수온   [22 ──●───────── 28 ] °C

이동 반경   ● 10km  ○ 30km  ○ 제주 전역     → 추천 후보 범위
주 활동 시간  □ 새벽 □ 오전 □ 오후 □ 일몰 □ 야간
```
- 이 값들은 Firestore `users/{uid}.activityProfile` 에 저장되고, `/api/v1/advice` 호출 시 서버에서 로드되어 §7.1의 가중치와 컷오프를 개인화한다.
- **미설정 사용자**에게는 §7.2의 일반 기본값을 적용하고, 3회 이상 방문 시 "내 조건 설정하면 더 정확해져요" 넛지 카드를 1회 노출한다.

### ③ 내 알림 (`/me/alerts`) — 규칙 빌더 (G13)
```
[+ 새 알림 만들기]

알림 유형
 ┌ A. 조건 알림 : 내가 정한 조건이 맞으면 알림
 │    대상 지점  [협재 해변 ▾]
 │    조건       파고 0.8~1.5m  AND  풍속 ≤ 6m/s  AND  풍향 W~NW
 │    확인 시점  ○ 매일 아침 6시  ● 조건 충족 즉시(최대 1일 2회)
 │    유효 기간  ○ 계속  ● 2026-10-31까지
 │
 ├ B. 물때 알림 : 만조/간조 N시간 전
 │    대상 지점, 이벤트(만조/간조), 사전 시간(10분~3시간)
 │
 ├ C. 안전 알림 (G8) : 갯벌·갯바위 활동 시
 │    "간조 1시간 전 복귀 알림" — 기본 ON 권장
 │    현재 위치 기반 자동 판단 옵션(위치 권한 필요, 기본 OFF)
 │
 ├ D. 특보 알림 : 기상특보·해상특보 발효/해제
 │    대상 지역, 특보 종류 선택
 │
 └ E. CCTV 복구 알림 : 즐겨찾는 CCTV가 다시 살아나면

공통 설정
  조용 시간   [22:00 ~ 07:00]  (안전 알림 C는 예외 — 조용시간 무시)
  채널        ☑ 웹 푸시   ☐ 이메일   (☐ 카카오 알림톡 — Phase 7)
  하루 최대   [5]건
```
- 규칙은 Firestore `users/{uid}/alertRules/{ruleId}` 에 저장.
- 평가 엔진: Cloud Functions 스케줄러 10분 주기 → 대상 지점 예보 조회 → 규칙 매칭 → FCM 발송 + `notifications` 컬렉션에 기록 (§14).
- 알림 이력 탭에서 "이 알림 유용했나요? 👍👎" 수집 → 규칙 튜닝 지표.

### ④ 내 기록 / 로그북 (`/me/logbook`) — **재방문을 만드는 기능**
서핑·낚시 앱들이 "조황 사진 공유"까지만 하는 데 반해, 바름닷컴은 **기록 시점의 기상·해양 조건 스냅샷을 자동 첨부**한다.

```
[+ 기록 추가]  (또는 CCTV·지점 화면의 "여기 기록하기" 버튼)

기록 항목
  날짜·시각 / 지점 / 활동 종류
  만족도 ★★★★☆
  메모 (자유)
  사진 (최대 5장, Firebase Storage)
  낚시일 때: 어종·마릿수·채비 (선택)
  서핑일 때: 보드·세션 시간 (선택)

▼ 자동 첨부 (사용자 입력 불필요)
  당시 기온 22.8° / 풍향·풍속 북서 4.1m/s / 파고 0.7m / 파주기 6.8s
  물때 8물 / 만조 07:42 / 간조 13:51 / 수온 24.0°
  출처·기준시각
```

**로그북이 만들어내는 것**
- `내 조건 통계`: "만족도 4점 이상이었던 날의 평균 파고 1.1m, 풍속 4.2m/s" → **"내 최적 조건" 자동 제안 → ② 활동 프로필에 1탭 반영**
- `연간 리포트`: 올해 몇 번 나갔는지, 어느 지점이 가장 좋았는지
- 캘린더 뷰 / 지도 뷰(내 기록이 찍힌 지점 히트맵)
- 내보내기: CSV / JSON (§9.4 ⑧ 데이터 이동권)
- 공개 범위: 기본 비공개. 개별 기록을 `공개`로 바꾸면 제보(⑤)로 승격 가능

### ⑤ 내 제보 (`/me/reports`)
- 사용자가 올린 현장 제보(사진 + 한 줄 + 자동 위치·시각) 목록과 상태(검토중/게시/반려)
- 신뢰도 점수: 채택률 기반. 일정 점수 이상이면 제보가 지도에 즉시 반영(어드민 사전 검수 생략)
- 제보 종류: 현재 파도 상태 / CCTV 오류 신고 / 위험 요소(이안류·낙석·쓰레기) / 데이터 오류 신고
- **데이터 오류 신고는 어드민의 데이터 품질 대시보드(§10.6)로 직결** — G14 대응

### ⑥ 저장한 여행/코스 (`/me/places` 내 탭 분리)
- 여행 탭에서 하트 누른 장소·코스
- "오늘 조건에 맞는 저장 장소" 필터 (조건 매칭 점수 재계산)

## 9.6 게이미피케이션 (가볍게, 선택)
- 등급: 기록 수 + 제보 채택 수 기반 `바다지기 Lv.1~5`
- 배지: `첫 기록`, `사리 마스터(사리 물때 5회 출조)`, `제주 서부 정복(서부 해변 10곳 방문)`, `안전 지킴이(안전 알림 활성)`
- **경쟁 순위표는 만들지 않는다** (안전 활동을 경쟁으로 만들면 위험)

# 10. 어드민 콘솔 (`/admin`)

## 10.1 설계 원칙
- **코드 배포 없이 운영 가능해야 한다.** CCTV가 죽고, 여행 콘텐츠가 바뀌고, 번역이 누락되는 일은 매주 일어난다.
- 어드민은 **데스크톱 우선 · 라이트 모드 기본**(서비스 앱은 다크 기본이지만 관리 화면은 밝게). 다크 모드도 지원한다.
- 별도 레이아웃(`app/admin/layout.tsx`), 로케일 라우팅 미적용(ko/en 토글만).
- **모든 쓰기 작업은 감사 로그**에 남는다.

## 10.2 권한 모델 (Firebase Custom Claims)

| 역할 | claim | 권한 |
|---|---|---|
| `superadmin` | `{role:'superadmin'}` | 전체 + 역할 부여 + 위험 작업(데이터 삭제, 전체 푸시) |
| `operator` | `{role:'operator'}` | CCTV·지점·데이터 소스 운영, 알림 발송(승인 필요) |
| `editor` | `{role:'editor'}` | 여행 콘텐츠·공지·번역 편집 |
| `moderator` | `{role:'moderator'}` | 제보·신고 검수 |
| `partner` | `{role:'partner', scope:['jeju-west']}` | 자기 관할 CCTV/장소만 조회·수정 |
| `viewer` | `{role:'viewer'}` | 읽기 전용 대시보드 |

- 클레임 부여는 `superadmin` 만 가능, Cloud Function `setUserRole` 경유.
- 미들웨어 + 각 `/api/admin/*` 라우트에서 **이중 검증**. Firestore 보안 규칙에도 동일 조건을 명시(§15.4).
- 2FA 필수(superadmin, operator): Firebase MFA(TOTP).

## 10.3 대시보드 (`/admin`)
```
상단 KPI 카드
  오늘 방문자 / 활성 세션 / 지도 로드 수 / API 호출 수(쿼터 대비 %) / 캐시 적중률 / 5xx 비율
실시간 위젯
  - 데이터 소스 헬스 (KMA / KHOA / GFS / ECMWF / Open-Meteo / CCTV) ← 신호등
  - CCTV 상태 요약 (온라인 38 / 불안정 1 / 오프라인 1)
  - 최근 오류 로그 10건
  - 미처리 제보 / 신고 건수
  - 번역 누락 건수 (로케일별)
지도 위젯
  - 지역별 조회 히트맵 (어느 지점이 인기인지 → 콘텐츠 우선순위 결정)
```
**KHOA API는 일일 20,000건 제한**이 있으므로, 쿼터 소진율은 대시보드 1순위 지표로 항상 노출한다.

## 10.4 콘텐츠 관리

### CCTV 관리 (`/admin/cctv`) — 운영 부하 1위
```
목록: 썸네일 / 이름(다국어) / 좌표 / 상태 / 최근 성공 / 평균 시작시간 / 제공기관
행 액션: 미리보기 재생 · 편집 · 숨김 · 삭제 · 지금 헬스체크
편집 폼:
  id, name{ko,en,zhCN,zhTW,ja}, lat/lng (지도 픽커), hlsUrl, backupHlsUrl,
  thumbnailUrl(자동 생성 가능), provider, attribution(표기 문구), tags[],
  linkedSpotId, enabled, sortOrder
자동화:
  - 5분 주기 헬스체크 Cloud Function → 3회 연속 실패 시 status='offline' + 목록에서 자동 숨김
  - 복구 감지 시 자동 재노출 + 구독자에게 복구 알림(§9.4 ③-E)
  - 썸네일: 10분 주기로 첫 프레임 캡처 → Storage 저장 (ffmpeg on Cloud Run)
일괄: CSV 업로드/다운로드
```

### 지점(Spot)·관측소 매핑 (`/admin/spots`)
```
지점 CRUD: id, name{5개 언어}, 좌표, 유형(beach|port|rock|mountain|poi),
           tideSystem(남해/서해), activityTags[], 대표 이미지,
           연결: kmaGrid{nx,ny} · khoaStation · 인근 CCTV · 부이
"관측소 자동 매핑" 버튼: 좌표 기준 최근접 관측소 3개 제안 + 거리 표시 → 수동 확정 (G14)
지점 상태 프리뷰: 실제 API를 호출해 현재 값이 정상 범위인지 확인
```

### 여행 콘텐츠 (`/admin/content`)
```
장소(places): 이미지, 설명{5개 언어}, 좌표, 카테고리, indoor 여부,
              bestTimeOfDay, activityTags, 추천 조건(파고/풍속 범위), 게시 상태
코스(courses): 장소 순서 배열, 소요시간, 배지(반나절/일몰/비와도OK), 설명{5개 언어}
공지/배너: 기간, 대상 로케일, 노출 화면, 우선순위
에디터: 리치 텍스트(제한적) + 이미지 업로드(자동 WebP 변환·리사이즈)
미리보기: 모바일/데스크톱 × 다크/라이트 × 로케일 선택 프리뷰
```

## 10.5 번역 관리 (`/admin/i18n`) — G11 운영 장치
```
매트릭스 뷰: [키] × [ko en zh-CN zh-TW ja]  → 누락 셀 빨강, 오래된 셀 노랑
필터: 누락만 / 화면별 / 최근 변경순
인라인 편집 + 기계번역 초안 생성 버튼(단, safety.* 네임스페이스는 기계번역 버튼 비활성 §8.3 L6)
Firestore 콘텐츠(L3/L4)의 다국어 필드도 같은 화면에서 관리
내보내기/가져오기: JSON, 번역 업체 전달용
```

## 10.6 데이터 품질·소스 모니터 (`/admin/data`)
```
소스별 카드: 최근 수집 시각 / 성공률(24h) / 평균 응답시간 / 쿼터 사용량 / 최근 실패 로그

```
