# 지도 화면과 PC 성능 기준

2026-09-29 사용자 지시: Windy.com에 기상청 초단기예보와 CCTV 등 지역 기능이 추가된 서비스로 개발한다. 기존 이용자가 익숙하게 조작할 수 있도록 화면 구성·배색을 가깝게 맞추고 PC의 지도 이동과 예보 탐색을 부드럽게 유지한다.

## 화면

- 지도를 화면 전체에 유지한다. 좌측 상단은 검색과 현재 위치, 우측은 기상 레이어, 하단은 5일 시간축·모델·색상 범례다.
- 지도 컨트롤은 작은 중성색 표면, 선택한 레이어는 붉은색, 선택 시간은 황색으로 표시한다. 다크·라이트 모두 CSS 토큰으로 관리한다.
- 기존 5개 메뉴의 목적지는 유지하되 데스크톱의 큰 측면 내비게이션은 작은 바로가기 모음으로 바꾼다. 모바일은 하단 내비게이션을 유지한다.
- 초단기예보는 선택 지점의 출처·기준 시각을 표시하는 드래그 가능한 패널로 연다. 지도 클릭 뒤 다른 지점의 상세 페이지로 이동하지 않는다.
- 한국 지점에 기상청 키가 있으면 현재 날씨는 초단기실황, 시간별 예보는 초단기예보를 우선한다. 시간별 예보의 실제 제공기관과 발표 시각을 현재 날씨와 별도로 표시한다. 키가 없거나 예보 호출이 실패하면 Open-Meteo 예보로 대체하고 출처를 바꾼다.
- CCTV 토글은 지도에 카메라 위치를 표시한다. 선택한 카메라만 패널에서 열고, 제공기관 페이지 방식의 카메라는 그 방식과 출처를 유지한다.
- 예보 레이어 변경 시 선택한 시간을 유지한다. 강수량으로 번개를 추측해 그리지 않는다. 시간은 모델 runAt 기준이며 한국 시간으로 표시한다.
- 실제 강수 격자가 없을 때는 대각선 띠로 보이던 합성 `BARUM_POC` 강수장을 제공하지 않는다. 지도 색상장을 숨기고 자료 부재를 명시한다. 다른 레이어에서 남은 색상장도 즉시 제거한다.

## 구현과 성능

- `raster.ts`에서 모델 격자를 Web Mercator 이미지로 한 번 변환하고 MapLibre ImageSource에 전달한다. 색상 레이어는 지도 라벨 아래에 배치한다. 지도 이동·확대는 GPU가 처리한다.
- 이전 구현의 이동마다 실행되던 화면 픽셀 순회와 파도 마스크용 반복 `queryRenderedFeatures`, 개별 픽셀 `getImageData`를 제거한다.
- 바람 입자는 별도 Canvas에 최대 720개(모바일 360개)로 제한한다. 지도를 움직일 때는 입자를 잠깐 멈추고 색상장은 계속 유지한다. 느린 프레임이 지속되면 입자를 줄인다.
- DPR은 1.5로 제한하고 입자 Canvas는 최대 300만 픽셀로 유지한다. 넓은 PC 모니터에서는 입자를 360개로 시작한다. 비활성 탭·reduced-motion·save-data에서는 입자 애니메이션을 멈추고, 복귀 또는 설정 변경 시 재개한다.
- 격자는 모델·변수·시간별 12개 LRU 캐시와 5분 TTL을 사용한다. 동일 요청은 공유하고 빠른 시간 이동은 80ms로 합친다. 늦게 끝난 이전 요청은 현재 화면을 덮어쓰지 못한다.
- 인접 시각 보간 시 변수·격자 크기·경계·모델·출처·runAt·단위가 같은지 검사한다. 실제 보간 시각을 validAt에 기록한다.

## 검증

- `tests/unit/grid-rendering.test.ts`: 요청 공유, 캐시 제한·만료·오류 재시도, Mercator 위도 변환, 무강수/결측 파도 투명도, 시각 보간 및 다른 모델 실행 혼합 방지. `grid-api.test.ts`는 라이브 강수 격자 부재 시 합성장을 제공하지 않고 실제 격자가 있으면 제공하는지 검사한다.
- `tests/unit/weather-bundle.test.ts`: 기상청 초단기예보 선택, 발표 시각 보존, 실패 시 Open-Meteo 폴백 출처, 한국 외 지역의 공식 API 호출 생략. `weather-sources.test.ts`는 HH30 발표 시각과 문자열 강수값을 검사한다.
- `tests/e2e/map-workspace.spec.ts`: 데스크톱·모바일 다크/라이트, 지도 패널·CCTV 토글, axe 접근성, 레이어 변경 시 시각 유지, URL 복원, 동일 구간 캐시 재사용, 강수 격자 부재 시 색상장 제거·안내, 이동 중 ImageData 재생성 방지, 3840×2160 화면의 입자 Canvas 300만 픽셀 상한.
- 브라우저 스크린샷은 `test-results/map-*.png`에 생성된다. 실제 기상 API 장애와 UI를 분리하기 위해 이 테스트의 지점 수치는 기존 목업 어댑터를 사용한다. 기상 격자 경로와 지도 타일은 앱 경로를 사용한다.
- 설치된 Chrome을 사용할 때는 `PLAYWRIGHT_CHANNEL=chrome`. 로컬 서버는 `localhost`로 바인딩한다.
- 2026-09-29 로컬 프로덕션 빌드 검증: 단위 테스트 76개, 데스크톱·모바일 E2E 12개 통과(데스크톱 전용 2개는 모바일에서 제외). 1280×720 Chrome의 120프레임 샘플에서 대기 및 이동 모두 60fps, 95백분위 프레임 시간 16.9/16.8ms. 3840×2160 Chrome에서 입자 Canvas 300만 픽셀 상한 통과. 번들 예산 180KiB 대비 지도 페이지 134.7KiB gzip.

## 실제 데이터와 남은 검증

- 기상청 공식 데이터에는 `KMA_SERVICE_KEY`가 필요하다. 현재 로컬 `.env.local`은 없다. 키가 없으면 기존 Open-Meteo 폴백을 사용하고 제공기관을 표시한다. 기상청 API는 매시 HH30 초단기예보를 HH45 이후에 요청하며 [공공데이터포털 단기예보 서비스](https://www.data.go.kr/data/15084084/openapi.do)의 제공 범위를 따른다.
- 로컬 모델 manifest가 없으면 바람·기온·파도에는 `BARUM_POC` 격자가 표시된다. 강수는 자료가 없다고 안내하고 색상장을 표시하지 않는다. 라이브 격자 수집·배포는 별도 설정이 필요하다.
- CCTV는 기존 레지스트리의 재생 허가와 `playbackMode`를 따른다. 제공기관 링크 방식은 직접 영상 스트림으로 변경하지 않는다.
- 중급 Android 50fps 및 실사용 PC의 다양한 GPU·4K 환경은 별도 실측이 필요하다. 자동 테스트는 불필요한 재계산 제거를 검증하며 모든 PC의 프레임 속도를 보장하지 않는다.
